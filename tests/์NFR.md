ข้อกำหนดความต้องการที่ไม่ใช่ฟังก์ชัน (Non-Functional Requirements)

1. ด้านประสิทธิภาพและการรองรับการใช้งาน (Performance & Scalability)

Response Time (ระยะเวลาตอบสนอง): ระบบต้องสามารถตอบสนองต่อคำสั่ง (API Requests) ในเส้นทางการเข้าสู่ระบบ (Login) และการเรียกดูข้อมูลผู้ใช้งานปัจจุบัน (Get Current User) โดยที่ 95% ของคำสั่งทั้งหมด (p95) ต้องใช้เวลาประมวลผลไม่เกิน 2 วินาที (2,000 มิลลิวินาที)

Concurrent Users (การรองรับผู้ใช้พร้อมกัน): ระบบต้องสามารถรองรับปริมาณผู้ใช้งานที่เข้ามาทำรายการเข้าสู่ระบบและดึงข้อมูลส่วนตัวพร้อมกัน (Concurrent Users) ได้สูงสุด 200 คน อย่างต่อเนื่องเป็นระยะเวลาอย่างน้อย 1 นาที โดยระบบยังคงทำงานได้ตามปกติ

Error Rate (อัตราข้อผิดพลาด): อัตราความล้มเหลวในการตอบสนองของระบบ (เช่น การคืนค่า HTTP Status Code ที่ไม่ใช่ 200 หรือเกิด Request Timeout) ตลอดการจำลองผู้ใช้งาน 200 คน จะต้องมีค่าน้อยกว่า 1%

2. ด้านความปลอดภัย (Security)

Authentication Enforcement: การเรียกดูข้อมูลผู้ใช้งาน (/users/me) ต้องได้รับการปกป้อง (Protected Route) โดยระบบจะอนุญาตให้เข้าถึงได้เฉพาะคำขอที่แนบ Access Token (Bearer Token) ที่ถูกต้องและได้มาจากการเข้าสู่ระบบสำเร็จเท่านั้น

3. ด้านความสามารถในการตรวจสอบและการรายงานผล (Observability & Reporting)

Automated Test Reporting: ระบบเครื่องมือทดสอบต้องสามารถสร้างและส่งออกรายงานสรุปผลการทดสอบ (Summary Results) ออกมาในรูปแบบไฟล์ JSON (loadtest-results.json) ได้โดยอัตโนมัติเมื่อสิ้นสุดการทำงาน เพื่อใช้ในการตรวจสอบค่า Metrics และเกณฑ์ Threshold ย้อนหลัง
